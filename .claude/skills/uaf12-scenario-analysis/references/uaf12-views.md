# UAF 1.2 视图映射与命名核对

目录:1 网格结构 · 2 视图使用表 · 3 核实状态 · 4 常见错误对照 · 5 与用户核对的话术

## 1 网格结构

UAF 1.2 以“视点(行)× 方面(列)”组织视图,视图编号 = 视点-方面。

- 视点:概述与摘要(Sm)、战略(St)、作战(Op)、服务(Sv)、人员、资源(Rs)、安全(Sc)、项目(Pj)、标准(Sd)、实际资源(Ar);部分资料还有架构管理(Am)。
- 方面:分类 Tx、结构 Sr、连通 Cn、过程 Pr、状态 St、顺序 Sq、信息 If、约束 Ct、路线图 Rm、追溯 Tr。

注意:方面“St”(状态)与视点“St”(战略)同缩写,写成 Op-St 是作战状态,St-Sr 是战略结构。人员视点缩写在不同资料中写作 Pr 或 Ps,**以用户插件为准**。

## 2 视图使用表(区域防空类场景)

| 视点       | 常用视图                                               | 放什么                                                       |
| ---------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| 概述与摘要 | Sm-Ov、Sm-Tx                                           | 场景概述、术语词典                                           |
| 战略       | St-Tx、St-Sr、St-Tr                                    | 能力分类、能力及依赖、能力与需求追溯                         |
| 作战       | Op-Tx、Op-Sr、Op-Cn、Op-Pr、Op-Sq、Op-St、Op-Ct、Op-Tr | 执行者类型、执行者结构、信息交换、作战活动、交互时序、目标状态、时间/阈值约束、活动追溯 |
| 服务       | Sv-Tx、Sv-Sr、Sv-Cn、Sv-Pr、Sv-Tr                      | 服务分类、结构、调用关系、服务内部流程、服务追溯             |
| 人员       | 分类、结构视图                                         | 指挥员等角色及其与资源的关系                                 |
| 资源       | Rs-Tx、Rs-Sr、Rs-Cn、Rs-Pr、Rs-Tr(Rs-Sq 若插件提供)    | 装备类型、结构与接口、系统功能、资源追溯                     |
| 实际资源   | Ar-Sr、Ar-Tr                                           | 装备实例、部署、实例到类型的追溯                             |

需求不是 UAF 1.2 的独立视点:用需求元素建模,并通过各 Tr 视图与 Satisfy/Verify 关系挂接。

## 3 核实状态

| 项目                                            | 状态                   | 依据与处理                                                   |
| ----------------------------------------------- | ---------------------- | ------------------------------------------------------------ |
| 作战视点的 8 个视图(Op-Tx/Sr/Cn/Pr/St/Sq/Ct/Tr) | 已核实                 | UAF 1.2 作战视点列表(Sparx EA 文档)。顺序视图是 Op-Sq,Op-Tr 是追溯 |
| 网格的视点×方面结构                             | 已核实                 | 多家工具文档一致                                             |
| Sv、Rs、St、Ar 各视点下的 Sr/Cn/Pr/Tr 等        | 按网格推定             | 命名规律一致,未逐个对照规范原文,建模前在插件中核对           |
| Rs-Sq 是否提供                                  | 未核实                 | 报告中标注“如插件提供”                                       |
| 概述与摘要 Sm、词典 Sm-Tx、架构管理 Am          | 未核实                 | 资料中 Sm-Ov/Sm-Tx 出现于较早或其他工具文档;1.2 中可能归入 Am 或名称有调整。让用户查看插件实际提供的“概述/词典”类图,再定稿 |
| 人员视点缩写(Pr 或 Ps)                          | 未核实                 | 以插件为准                                                   |
| 安全 Sc、项目 Pj、标准 Sd                       | 存在但本技能默认不展开 | 场景有安全、项目、标准要求时再加                             |

处理原则:已核实的直接用;推定的用,但报告“说明”段写明“以插件实际视图为准”;未核实的先写“视图以插件为准”,并提示用户核对。

## 4 常见错误对照

| 常见错误写法               | 正确写法                               |
| -------------------------- | -------------------------------------- |
| Op-Tr 表示交互时序         | 时序用 Op-Sq,Op-Tr 是追溯              |
| 执行者结构放在 Op-Tx/Op-Cn | 类型放 Op-Tx,结构放 Op-Sr,连通放 Op-Cn |
| Sv-Fn、Rs-Fn(功能)         | Sv-Pr、Rs-Pr                           |
| Rs-Tr 当作资源交互         | Rs-Tr 是追溯                           |
| Rq 作为视点                | 用需求元素 + Tr 视图 + Satisfy/Verify  |
| 把 Dc 当成 1.2 的视点编号  | 先让用户核对插件里词典放在何处         |
| 能力依赖写作 St-Cn         | 优先用 St-Sr(以插件为准)               |

## 5 与用户核对的话术

遇到未核实项时,简短问:“请在 MagicDraw 新建 UAF 图时,看看顶层有哪些视点,‘概述/词典/架构管理’类的图叫什么名字,告诉我后我统一修改。”只问这一个问题,其余先按“以插件为准”处理。
